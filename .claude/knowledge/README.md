# 구운록 자동 학습 지식 베이스 (Auto-Learning Knowledge Base)

사용자가 자리에 없는 평상시에도 Claude가 스스로 리서치를 돌려서,
프로젝트에 필요한 최신 정보·기술·디자인 지식을 쌓아두는 공간입니다.
개발 세션이 시작되면 이 지식 베이스를 먼저 읽고, 최신 학습 내용을 반영해서 개발합니다.

## 동작 방식

1. **예약 루틴(Routine)** 이 매일 정해진 시간(03:00 KST)에 새 Claude 세션을 자동으로 띄웁니다.
2. 그 세션은 `research-queue.md`에서 우선순위가 높은 주제를 1~2개 골라 웹 리서치를 합니다.
3. 결과를 `topics/` 아래에 주제별 노트로 저장하고, `INDEX.md`와 `learning-log.md`를 갱신합니다.
4. 변경 사항은 `claude/knowledge-base` 브랜치에 커밋/푸시됩니다.
5. 이후 개발 세션은 CLAUDE.md의 지시에 따라 이 지식을 읽고 최신 정보 기반으로 개발합니다.

## 디렉터리 구조

```
.claude/knowledge/
├── README.md          ← 이 파일 (시스템 설명)
├── INDEX.md           ← 지식 인덱스 (주제, 요약, 최종 갱신일)
├── research-queue.md  ← 학습 주제 큐 (사용자가 자유롭게 추가 가능)
├── learning-log.md    ← 학습 세션 기록
├── ROUTINE.md         ← 자동 학습 루틴의 사양과 프롬프트 사본
└── topics/            ← 실제 지식 노트
    ├── game-design/   ← 게임 디자인 (밸런싱, 카드 시너지, 로그라이크 구조 등)
    ├── frontend/      ← Next.js, React, Tailwind 등 기술 스택
    ├── ux/            ← 모바일 웹 게임 UI/UX
    └── workflow/      ← 바이브 코딩·개발 자동화 워크플로
```

## 지식 노트 작성 규칙 (자동 학습 세션용)

- 노트 하나 = 주제 하나. 파일명은 영문 케밥케이스 (`deckbuilder-balancing.md`).
- 맨 위에 메타데이터: 최종 갱신일, 출처 링크, 신뢰도 메모.
- **구운록에 어떻게 적용할지**(`## 구운록 적용 아이디어` 섹션)를 반드시 포함할 것.
  일반론만 쌓이면 쓸모가 없습니다. 항상 이 프로젝트 기준으로 번역해서 기록.
- 기존 노트를 갱신할 때는 덮어쓰지 말고, 낡은 정보는 취소선이나 "(구버전)" 표시 후 최신 정보를 추가.
- 코드 변경은 하지 않습니다. 자동 학습 세션은 `.claude/knowledge/` 아래 파일만 수정합니다.

## 사용자(사람)를 위한 조작법

- **주제 추가**: `research-queue.md`에 한 줄 추가하면 다음 학습 때 반영됩니다.
- **일시정지/재개**: Claude에게 "자동 학습 루틴 꺼줘/켜줘"라고 말하면 됩니다.
- **주기 변경**: "자동 학습을 주 2회로 바꿔줘" 등으로 요청.
- **지식 반영**: 개발 세션에서 "지식 베이스 최신 내용 반영해서 ~해줘"라고 하면
  `claude/knowledge-base` 브랜치의 최신 노트를 가져와 적용합니다.
